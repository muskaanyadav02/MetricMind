\# MetricMind Data Dictionary



\## 1. Overview



MetricMind uses a layered data architecture to transform the Global Superstore

transaction dataset into a governed analytical data model.



```text

Global Superstore CSV

&#x20;       ↓

Snowflake RAW

&#x20;       ↓

dbt STAGING

&#x20;       ↓

dbt INTERMEDIATE

&#x20;       ↓

dbt MART

&#x20;       ↓

Star Schema

&#x20;       ↓

Cube Semantic Layer







The analytical model follows a star-schema design with one central fact table

and multiple dimension tables.



2\. Source Dataset

Global Superstore



The source dataset contains 51,290 transaction-level records and 27 columns.



Dataset Characteristics

Attribute	Value

Total rows	51,290

Columns	27

Unique orders	25,035

Unique customers	4,873

Unique products	10,292

Years	2011–2014

Duplicate rows	0

Missing values	0

Source Grain



The source dataset is at order-line / transaction-line grain.



One order can contain multiple products and therefore multiple rows.



Therefore:



ROW\_ID identifies an individual transaction row.

ORDER\_ID identifies an order.

Orders must be calculated using COUNT(DISTINCT ORDER\_ID).

Row count must not be treated as the number of orders.

4\. fact\_sales

Purpose



Contains transaction-level sales records used for analytical calculations.



Grain



One row represents one transaction/order-line record.



Row Count



51,290 rows.



Columns

Column	Description

ROW\_ID	Unique identifier for each transaction row

ORDER\_ID	Identifier of the order

ORDER\_DATE	Date and time when the order was placed

SHIP\_DATE	Date and time when the order was shipped

CUSTOMER\_ID	Customer identifier

PRODUCT\_ID	Product identifier

CITY	City associated with the transaction

STATE	State associated with the transaction

COUNTRY	Country associated with the transaction

REGION	Geographic region

MARKET	Business market

MARKET2	Secondary market classification

ORDER\_PRIORITY	Priority assigned to the order

SHIP\_MODE	Shipping method

QUANTITY	Quantity sold

SALES	Sales revenue

DISCOUNT	Discount applied to the transaction

PROFIT	Profit generated by the transaction

SHIPPING\_COST	Shipping cost

YEAR	Order year

WEEKNUM	Order week number

PROFIT\_MARGIN\_PERCENT	Calculated transaction-level profit margin

HAS\_DISCOUNT	Boolean indicating whether a discount was applied

Important Business Rule



Official profit margin is calculated at the aggregate level:



SUM(PROFIT) / SUM(SALES) \* 100



The transaction-level PROFIT\_MARGIN\_PERCENT column is useful for row-level analysis but should not be averaged to calculate the official overall profit margin.

7\. dim\_geography

Purpose



Contains geographic and market attributes used for regional analysis.



Row Count



3,819 geographic combinations.



Columns

Column	Description

CITY	City

STATE	State

COUNTRY	Country

REGION	Geographic region

MARKET	Business market

MARKET2	Secondary market classification

Business Use



The geography dimension supports analysis such as:



Sales by country

Profit by region

Market performance

City-level performance

European market analysis

Important Note



Europe is represented by:



MARKET = 'EU'



and should not be inferred from the REGION column.
